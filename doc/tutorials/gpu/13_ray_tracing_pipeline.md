# Tutorial 13: Ray Tracing Pipeline — Cornell Box Path Tracer

This tutorial walks through the `13_ray_tracing_pipeline` example: a full path tracer that renders a Cornell box scene using the `bg2e::gpu` ray tracing pipeline. Unlike tutorial 11 (which uses ray queries alongside rasterization), this example replaces rasterization entirely — every pixel is generated by tracing rays through a scene with Monte Carlo integration and progressive accumulation.

**Source:** `examples/gpu/13_ray_tracing_pipeline/src/main.cpp`

- How to load ray generation, miss, and closest hit shaders via `ShaderLib`

- How to build Cornell box geometry with per-instance material data

## Understanding path tracing

Path tracing is a Monte Carlo method for approximating the rendering equation. Unlike rasterization (which evaluates lighting analytically) or rasterization + ray queries (which cast a limited set of auxiliary rays), path tracing traces multiple random light paths per pixel and averages the results.

```
Rasterization + Ray Query              Path Tracing (Ray Tracing Pipeline)
┌──────────────────────┐              ┌──────────────────────┐
│ Draw geometry with   │              │ For each pixel:      │
│ forward lighting     │              │   Generate camera ray│
│                      │              │   for bounce = 0..N: │
│ Fragment shader:     │              │     traceRay()       │
│   N.L lighting       │              │     if miss: break   │
│   ray query shadow   │              │     accumulate color │
│   (1 ray per frag)   │              │     bounce randomly  │
│                      │              │   tone map result    │
└──────────────────────┘              └──────────────────────┘
  Uses rasterization pipeline           Uses ray tracing pipeline
  Limited to shadow rays                Full light transport
  Real-time friendly                    Converges over time
```

The ray tracing pipeline (`RayTracingPipeline`) dispatches rays across the entire image. The ray generation shader (`main` in `.rgen`) runs once per pixel (or sub-pixel sample) and can call `traceRayEXT()` to cast rays. Each ray that hits geometry invokes the closest hit shader (`.rchit`), and rays that miss invoke the miss shader (`.rmiss`). This example chains up to 8 bounces per path.

**Reference:** [GPU API -- RayTracingPipeline](../../api/gpu/RayTracingPipeline.md)

## Step-by-step code explanation

### 1. Data structures

```cpp
struct CameraData {
    glm::mat4 viewInverse;
    glm::mat4 projInverse;
    glm::vec4 misc; // x=frameCount, y=width, z=height
};

struct InstanceData {
    glm::vec4 albedo;         // rgb albedo, a = roughness
    glm::vec4 emission;       // rgb emission, a = shapeType
    glm::vec4 normalOrCenter; // plane: world normal; sphere/cube: world center; w = sphere radius
    glm::vec4 extents;        // cube: world-space half-extents
};

enum class ShapeType : int { Plane = 0, Sphere = 1, Cube = 2 };
```

Two structs define the per-frame and per-instance data:

- **`CameraData`**: inverse view and projection matrices (needed to reconstruct rays from pixel coordinates), plus a `misc` vec4 carrying the frame count, image width, and image height
- **`InstanceData`**: per-surface material and shape description. The `shapeType` (packed in `emission.a`) tells the closest hit shader how to compute the surface normal analytically — no per-vertex normals are needed

The `normalOrCenter` and `extents` fields encode geometry-specific parameters:
- **Plane**: world-space normal in `.xyz`
- **Sphere**: world-space center in `.xyz`, radius in `.w`
- **Cube**: world-space center in `.xyz`, half-extents in `extents.xyz`

**Reference:** [GPU API -- PipelineLayout: Resource bindings](../../api/gpu/PipelineLayout.md#resource-bindings)

### 2. Ray tracing capability detection

```cpp
if (!physicalDevice->properties()->rayTracingSupported())
{
    std::cerr << "Ray tracing not supported by the selected GPU" << std::endl;
    SDL_DestroyWindow(window);
    SDL_Quit();
    return 1;
}
```

Before creating any acceleration structures or ray tracing pipelines, the example checks that the GPU supports ray tracing. The `rayTracingSupported()` method returns `true` only when all required capabilities are present.

**Reference:** [GPU API -- PhysicalDeviceProperties: RayTracingCapabilities](../../api/gpu/PhysicalDeviceProperties.md#raytracingcapabilities)

### 3. Loading ray tracing shaders

```cpp
auto shaderBasePath = base::PlatformTools::shaderPath();
auto shaderLib = backend->createShaderLib(shaderBasePath / "gpu_ray_tracing_pipeline");
auto rgen = shaderLib->rayGeneration("ray_tracing_pipeline", device.get());
auto rmiss = shaderLib->miss("ray_tracing_pipeline", device.get());
auto rchit = shaderLib->closestHit("ray_tracing_pipeline", device.get());
cleanup.push(rgen);
cleanup.push(rmiss);
cleanup.push(rchit);
```

The `ShaderLib` loads compiled ray tracing shader modules from a flat directory. The naming convention resolves the file paths automatically:

| Method | Stage | Vulkan file | Metal file | Vulkan entry | Metal entry |
|--------|-------|-------------|------------|--------------|-------------|
| `rayGeneration()` | `.rgen` | `.rgen.spv` | `.rgen.metallib` | `main` | `rgenMain` |
| `miss()` | `.rmiss` | `.rmiss.spv` | `.rmiss.metallib` | `main` | `rmissMain` |
| `closestHit()` | `.rchit` | `.rchit.spv` | `.rchit.metallib` | `main` | `rchitMain` |

On Metal, `miss()` and `closestHit()` may return `nullptr` — Metal handles those stages internally in the compute kernel. The `RayTracingPipeline` accepts null pointers for these shaders without error.

**Reference:** [GPU API -- ShaderLibraries: Stage extension mapping](../../api/gpu/ShaderLibraries.md#stage-extension-mapping)

### 4. Pipeline layout with storage images, UBO, acceleration structure, and SSBO

```cpp
gpu::PipelineLayoutDescription layoutDesc{};
layoutDesc.resourceBindings.push_back({
    0, {.vulkan = 0, .metal = 0}, gpu::ResourceType::StorageImage,
    gpu::ShaderStage::RayGeneration, 1
});
layoutDesc.resourceBindings.push_back({
    0, {.vulkan = 1, .metal = 1}, gpu::ResourceType::UniformBuffer,
    gpu::ShaderStage::RayGeneration, 1
});
layoutDesc.resourceBindings.push_back({
    0, {.vulkan = 2, .metal = 1}, gpu::ResourceType::StorageImage,
    gpu::ShaderStage::RayGeneration, 1
});
layoutDesc.resourceBindings.push_back({
    1, {.vulkan = 0, .metal = 2}, gpu::ResourceType::AccelerationStructure,
    gpu::ShaderStage::RayGeneration, 1
});
layoutDesc.resourceBindings.push_back({
    2, {.vulkan = 0, .metal = 3}, gpu::ResourceType::StorageBuffer,
    gpu::ShaderStage::ClosestHit, 1
});
layoutDesc.debugName = "RT pipeline layout";
auto layout = device->createPipelineLayout(layoutDesc);
```

The layout defines three descriptor sets:

| Set | Vulkan Binding | Metal Index | Type | Stage | Purpose |
|-----|---------------|-------------|------|-------|---------|
| 0 | 0 | texture(0) | StorageImage | RayGeneration | Output image (R8G8B8A8) |
| 0 | 1 | buffer(1) | UniformBuffer | RayGeneration | Camera data UBO |
| 0 | 2 | texture(1) | StorageImage | RayGeneration | Accumulation image (RGBA32F) |
| 1 | 0 | buffer(2) | AccelerationStructure | RayGeneration | Top-level acceleration structure |
| 2 | 0 | buffer(3) | StorageBuffer | ClosestHit | Per-instance material/shape data SSBO |

Note that **set 0 uses two `StorageImage` bindings** — the 8-bit output image (for the final swapchain copy) and the 32-bit float accumulation image (for the Monte Carlo running average). The closest hit shader accesses the instance data SSBO at set 2, which it uses to look up material properties via `gl_InstanceCustomIndexEXT`.

**Reference:** [GPU API -- PipelineLayout: Resource bindings](../../api/gpu/PipelineLayout.md#resource-bindings)

### 5. Output and accumulation image creation

```cpp
auto outputImage = device->createImage({
    {kWindowWidth, kWindowHeight}, gpu::PixelFormat::R8G8B8A8_UNORM,
    gpu::ImageUsage::Storage | gpu::ImageUsage::TransferSrc,
    gpu::ImageType::Image2D, 1, 0, "RT output image"
});
cleanup.push(outputImage);

auto accumImage = device->createImage({
    {kWindowWidth, kWindowHeight}, gpu::PixelFormat::R32G32B32A32_SFLOAT,
    gpu::ImageUsage::Storage,
    gpu::ImageType::Image2D, 1, 0, "RT accumulation image"
});
cleanup.push(accumImage);
```

Two images are created for the render target:

- **Output image** (`R8G8B8A8_UNORM`): a 4-byte-per-pixel format compatible with the swapchain. The final `copyImage()` command copies this directly into the swapchain's color image as a 1:1 texel copy. This format is the portable storage format that supports `read_write` on both Vulkan and Metal.
- **Accumulation image** (`R32G32B32A32_SFLOAT`): a 16-byte-per-pixel floating-point format used to store the running average of the Monte Carlo samples. An 8-bit format would cause banding and prevent convergence. The path tracer blends each new frame into this image with weight `1/frameCount`, producing a progressive refinement.

**Reference:** [GPU API -- Image](../../api/gpu/Image.md)

### 6. Camera UBO

```cpp
float aspect = static_cast<float>(kWindowWidth) / static_cast<float>(kWindowHeight);
auto projection = glm::perspective(glm::radians(40.0f), aspect, 0.1f, 100.0f);
auto view = glm::lookAt(
    glm::vec3(0.0f, 2.7f, 15.0f),  // camera position
    glm::vec3(0.0f, 2.7f, 0.0f),   // look-at center
    glm::vec3(0.0f, 1.0f, 0.0f)
);

CameraData camData{};
camData.viewInverse = glm::inverse(view);
camData.projInverse = glm::inverse(projection);
camData.misc = glm::vec4(1.0f, static_cast<float>(kWindowWidth), static_cast<float>(kWindowHeight), 0.0f);

auto cameraUbo = device->createBuffer("Camera UBO");
cameraUbo->createUniformBuffer(camData);
cleanup.push(cameraUbo);
```

The camera UBO stores the **inverse** view and projection matrices. The ray generation shader uses these to reconstruct a camera ray from pixel coordinates — the standard technique in ray tracing shaders. Storing inverses avoids computing them per-pixel in the shader.

The `misc` field passes the frame count (for progressive accumulation), image width, and image height to the shader.

**Reference:** [GPU API -- Buffer: createUniformBuffer()](../../api/gpu/Buffer.md#createuniformbuffer)

### 7. Cornell box geometry creation

```cpp
struct ScenePiece {
    std::shared_ptr<gpu::MeshPN> mesh;
    glm::mat4 model = glm::mat4(1.0f);
    InstanceData instance{};
    std::vector<std::shared_ptr<gpu::RayTracingMesh>> rtMeshes;
};
```

Each geometry piece carries:

- **`mesh`**: the rasterization mesh (`MeshPN` = position + normal) — reused for BLAS vertex/index buffers
- **`model`**: world transform matrix
- **`instance`**: material and shape data (albedo, emission, roughness, shape type, center/normal)
- **`rtMeshes`**: one `RayTracingMesh` per submesh — the bottom-level acceleration structures

The `addPiece` lambda creates the mesh, sets up instance data, and builds `RayTracingMesh` objects:

```cpp
auto addPiece = [&](bg2e::geo::MeshPN* data, const glm::mat4& model,
                    ShapeType shapeType, float roughness,
                    const glm::vec3& albedo, const glm::vec3& emission,
                    const glm::vec4& shapeParam = glm::vec4(0.0f))
{
    auto piece = std::make_shared<ScenePiece>();
    piece->mesh = std::make_shared<gpu::MeshPN>();
    piece->mesh->setMeshData(*data);
    piece->mesh->build(device.get());
    piece->model = model;

    InstanceData& inst = piece->instance;
    inst.albedo   = glm::vec4(albedo, roughness);
    inst.emission = glm::vec4(emission, static_cast<float>(shapeType));

    const glm::vec3 center = glm::vec3(model[3]);
    switch (shapeType)
    {
        case ShapeType::Plane:
            inst.normalOrCenter =
                glm::vec4(glm::normalize(glm::mat3(model) * glm::vec3(0.0f, 1.0f, 0.0f)), 0.0f);
            break;
        case ShapeType::Sphere:
            inst.normalOrCenter = glm::vec4(center, shapeParam.w);
            break;
        case ShapeType::Cube:
            inst.normalOrCenter = glm::vec4(center, 0.0f);
            inst.extents        = glm::vec4(glm::vec3(shapeParam), 0.0f);
            break;
    }

    for (uint32_t s = 0; s < piece->mesh->submeshCount(); ++s)
    {
        piece->rtMeshes.push_back(
            device->createRayTracingMesh(piece->mesh->rayTracingMeshDescription(s))
        );
    }

    pieces.push_back(piece);
    delete data;
};
```

The scene is built with 8 pieces:

| Piece | Shape | Position | Albedo | Emission | Roughness |
|-------|-------|----------|--------|----------|-----------|
| Floor | Plane | (0, 0, 0) | (0.73, 0.73, 0.73) | none | 0.5 |
| Ceiling | Plane | (0, 5.5, 0) | (0.73, 0.73, 0.73) | none | 0.5 |
| Back wall | Plane | (0, 2.75, -2.75) | (0.73, 0.73, 0.73) | none | 0.5 |
| Left wall | Plane | (-2.75, 2.75, 0) | (0.63, 0.06, 0.06) | none | 0.5 |
| Right wall | Plane | (2.75, 2.75, 0) | (0.12, 0.45, 0.15) | none | 0.5 |
| Light | Plane | (0, 5.49, 0) | (0, 0, 0) | (18, 18, 18) | 0.5 |
| Cube | Cube | (-1, 0.6, 0.5) | (0.95, 0.95, 0.95) | none | 0.0 |
| Sphere | Sphere | (1.2, 0.6, -0.5) | (0.95, 0.95, 0.95) | none | 0.0 |

The walls use roughness 0.5 (matte Lambertian), while the cube and sphere are shiny (roughness 0.0, mirror-like). The light rectangle has black albedo with high emission — when a ray hits it, it accumulates emission and the black albedo kills the throughput, terminating the path.

**Reference:** [GPU API -- RayTracingMesh: Usage](../../api/gpu/RayTracingMesh.md#usage)

### 8. Building BLAS (bottom-level acceleration structures)

```cpp
device->immediateSubmit([&](gpu::CommandBuffer* cmd)
{
    for (auto& piece : pieces)
    {
        for (auto& rtMesh : piece->rtMeshes)
        {
            cmd->buildRayTracingMesh(rtMesh.get());
        }
    }
});
```

Each `RayTracingMesh` is built with a single `immediateSubmit` call. The `buildRayTracingMesh()` command records the backend-specific build:

- **Vulkan**: `vkCmdBuildAccelerationStructuresKHR`
- **Metal**: build on a `MTL::AccelerationStructureCommandEncoder`

The acceleration structure storage and scratch buffers were allocated at `createRayTracingMesh()` time — only the actual build is a GPU command. The `immediateSubmit` call blocks until all BLAS builds complete.

**Reference:** [GPU API -- RayTracingMesh: Usage](../../api/gpu/RayTracingMesh.md#usage), [GPU API -- Device::immediateSubmit()](../../api/gpu/Device.md)

### 9. Creating the TLAS (top-level acceleration structure)

```cpp
auto rayTracingScene = device->createRayTracingScene("Cornell box scene");
cleanup.push(rayTracingScene);

uint32_t instanceId = 0;
for (auto& piece : pieces)
{
    for (auto& rtMesh : piece->rtMeshes)
    {
        rayTracingScene->addInstance(rtMesh.get(), piece->model, instanceId++, 0xFF);
        allInstanceData.push_back(piece->instance);
    }
}

device->immediateSubmit([&](gpu::CommandBuffer* cmd)
{
    rayTracingScene->buildOrUpdate(cmd);
});
```

The `RayTracingScene` is the top-level acceleration structure. The instance list is built by calling `addInstance()` for each submesh with:

- **`mesh`**: the `RayTracingMesh` to instance
- **`model`**: world transform matrix
- **`instanceId`**: sequential counter that maps to `gl_InstanceCustomIndexEXT` in the shader — this is the key that links each BLAS instance to its `InstanceData` entry in the SSBO
- **`0xFF`**: visibility mask (all bits set, visible to all rays)

The `allInstanceData` vector is built in lock-step with the instances. When the closest hit shader reads `instances.data[gl_InstanceCustomIndexEXT]`, it gets the correct material and shape data.

**Reference:** [GPU API -- RayTracingScene: Usage](../../api/gpu/RayTracingScene.md#usage)

### 10. Instance data SSBO

```cpp
auto instanceBuffer = device->createBuffer("Instance Data SSBO");
instanceBuffer->createStorageBuffer(allInstanceData.data(),
    allInstanceData.size() * sizeof(InstanceData));
cleanup.push(instanceBuffer);
```

The `InstanceData` array is uploaded to a storage buffer (SSBO). This is a host-visible buffer created with `createStorageBuffer()`, which copies the initial data from the CPU vector.

The SSBO is bound to descriptor set 2 and accessed in the closest hit shader as:

```glsl
layout(set = 2, binding = 0) buffer InstanceBuffer { InstanceData data[]; } instances;
```

**Reference:** [GPU API -- Buffer: createStorageBuffer()](../../api/gpu/Buffer.md#createstoragebuffer)

### 11. Resource set creation

```cpp
auto outputSet = device->createResourceSet(layout.get(), 0, "Output set");
outputSet->setStorageImage({.vulkan = 0, .metal = 0}, outputImage.get());
outputSet->setUniformBuffer({.vulkan = 1, .metal = 1}, cameraUbo.get());
outputSet->setStorageImage({.vulkan = 2, .metal = 1}, accumImage.get());
outputSet->update();
cleanup.push(outputSet);

auto sceneSet = device->createResourceSet(layout.get(), 1, "Scene set");
sceneSet->setRayTracingScene({.vulkan = 0, .metal = 2}, rayTracingScene.get());
sceneSet->update();
cleanup.push(sceneSet);

auto dataSet = device->createResourceSet(layout.get(), 2, "Data set");
dataSet->setStorageBuffer({.vulkan = 0, .metal = 3}, instanceBuffer.get());
dataSet->update();
cleanup.push(dataSet);
```

Three resource sets map to the three descriptor sets in the pipeline layout:

| Set | Contents | Bound to |
|-----|----------|----------|
| 0 | Output image (storage), Camera UBO, Accumulation image (storage) | Ray generation shader |
| 1 | RayTracingScene (acceleration structure) | Ray generation shader |
| 2 | Instance data SSBO (storage buffer) | Closest hit shader |

The `ShaderBinding` struct uses `.vulkan` for the descriptor binding index and `.metal` for the Metal argument index. Metal texture indices can start at 0 (separate namespace from buffers), while Metal buffer indices for compute stages must be >= 1 (index 0 is reserved for push constants).

**Reference:** [GPU API -- ResourceSet: Metal binding rules](../../api/gpu/ResourceSet.md#metal-binding-rules)

### 12. RayTracingPipeline creation

```cpp
gpu::RayTracingPipelineDescription pipelineDesc{};
pipelineDesc.raygenShader = rgen.get();
pipelineDesc.missShader = rmiss.get();
pipelineDesc.closestHitShader = rchit.get();
pipelineDesc.layout = layout.get();
pipelineDesc.maxRecursionDepth = 1;
pipelineDesc.debugName = "Cornell box RT pipeline";
auto rtPipeline = device->createRayTracingPipeline(pipelineDesc);
cleanup.push(rtPipeline);
```

The pipeline is created from the three shader modules and the layout:

- **`raygenShader`**: the ray generation shader (required on all backends)
- **`missShader`**: the miss shader (nullable on Metal)
- **`closestHitShader`**: the closest hit shader (nullable on Metal)
- **`layout`**: the pipeline layout with all resource bindings
- **`maxRecursionDepth = 1`**: rays are traced with recursion depth 1 (the path tracing loop is implemented iteratively in the ray generation shader, not via recursive traceRay calls)

On Vulkan, the pipeline owns a Shader Binding Table (SBT) that maps the ray types to shader stages. On Metal, the pipeline wraps an `MTLComputePipelineState` loaded from the ray generation shader's metallib.

**Reference:** [GPU API -- RayTracingPipeline: Architecture](../../api/gpu/RayTracingPipeline.md#architecture)

### 13. Render loop with progressive accumulation

```cpp
auto& graphicsQueue = device->graphicsQueue();
uint32_t frameCount = 0;
bool running = true;
glm::mat4 lastView = camData.viewInverse;
glm::mat4 lastProj = camData.projInverse;

while (running)
{
    SDL_Event event;
    while (SDL_PollEvent(&event))
    {
        if (event.type == SDL_QUIT) running = false;
        if (event.type == SDL_WINDOWEVENT &&
            event.window.event == SDL_WINDOWEVENT_CLOSE) running = false;
        if (event.type == SDL_WINDOWEVENT &&
            event.window.event == SDL_WINDOWEVENT_RESIZED)
        {
            // ... resize handling (see section 14)
        }
    }

    if (camData.viewInverse != lastView || camData.projInverse != lastProj)
    {
        frameCount = 0;
        lastView = camData.viewInverse;
        lastProj = camData.projInverse;
    }

    frameCount++;
    camData.misc.x = static_cast<float>(frameCount);
    cameraUbo->updateUniformBuffer(camData);
```

The render loop tracks a `frameCount` that drives the progressive accumulation. Each frame:

1. The frame count is incremented and written to `camData.misc.x`
2. The camera UBO is updated with the new frame count
3. If the camera changes (not implemented in this example, but the tracking is present), `frameCount` resets to 0

The progressive accumulation works as a running mean. The ray generation shader blends each new frame's color with the accumulated result using weight `1/frameCount`:

```glsl
float frameCount = cam.misc.x;
vec3 prev = imageLoad(accumImage, ivec2(gl_LaunchIDEXT.xy)).rgb;
vec3 accum = (frameCount <= 1.0) ? radiance
                                  : mix(prev, radiance, 1.0 / frameCount);
imageStore(accumImage, ivec2(gl_LaunchIDEXT.xy), vec4(accum, 1.0));
```

This produces a progressively refined image — the first frame is noisy, but the noise decreases as more frames accumulate. The frame count must be reset to 0 whenever the accumulated result becomes invalid (camera moved, window resized).

### 14. Ray tracing dispatch

```cpp
auto frame = surface->beginFrame();
if (!frame) continue;

auto cmd = graphicsQueue.createCommandBuffer("Frame");

cmd->begin();

cmd->transition(outputImage.get(), gpu::ImageLayout::General);
cmd->transition(accumImage.get(), gpu::ImageLayout::General);

cmd->bindPipeline(rtPipeline.get());
cmd->bindResourceSet(rtPipeline.get(), 0, outputSet.get());
cmd->bindResourceSet(rtPipeline.get(), 1, sceneSet.get());
cmd->bindResourceSet(rtPipeline.get(), 2, dataSet.get());
cmd->traceRays(outputImage->width(), outputImage->height(), 1);
```

The dispatch sequence:

1. **Transition images to `General` layout**: storage images must be in the `General` layout for shader read/write access
2. **Bind the RT pipeline**: selects the ray tracing pipeline for subsequent `traceRays()` calls
3. **Bind resource sets**: binds all three descriptor sets (output, scene, data)
4. **Trace rays**: dispatches the ray generation shader across the entire image width × height

On Vulkan, `traceRays()` calls `vkCmdTraceRaysKHR` with the pipeline's internal SBT. On Metal, it dispatches the rgen compute kernel as `ceil(width/8) × ceil(height/8) × 1` threadgroups.

### 15. Copy to swapchain and present

```cpp
cmd->transition(outputImage.get(), gpu::ImageLayout::TransferSrc);
cmd->transition(frame->colorImage(), gpu::ImageLayout::TransferDst);
cmd->copyImage(outputImage.get(), frame->colorImage());
cmd->transition(frame->colorImage(), gpu::ImageLayout::Present);

surface->present(cmd.get());

cmd->end();
graphicsQueue.submit(cmd.get());
surface->endFrame(frame.get());
```

After tracing:

1. The output image is transitioned to `TransferSrc`
2. The swapchain color image is transitioned to `TransferDst`
3. `copyImage()` performs a 1:1 texel copy from the 8-bit output image to the swapchain
4. The swapchain image is transitioned to `Present`
5. The frame is presented

The output image is an `R8G8B8A8_UNORM` format that is byte-compatible with the swapchain's `BGRA8` format (the shader writes `.bgr` swizzled channels to account for this).

### 16. Window resize handling

```cpp
if (event.type == SDL_WINDOWEVENT &&
    event.window.event == SDL_WINDOWEVENT_RESIZED)
{
    uint32_t newWidth  = static_cast<uint32_t>(event.window.data1);
    uint32_t newHeight = static_cast<uint32_t>(event.window.data2);
    device->waitIdle();
    surface->resize({newWidth, newHeight});

    outputImage->cleanup();
    auto newOutput = device->createImage({
        {newWidth, newHeight}, gpu::PixelFormat::R8G8B8A8_UNORM,
        gpu::ImageUsage::Storage | gpu::ImageUsage::TransferSrc,
        gpu::ImageType::Image2D, 1, 0, "RT output image"
    });
    cleanup.push(newOutput);

    accumImage->cleanup();
    auto newAccum = device->createImage({
        {newWidth, newHeight}, gpu::PixelFormat::R32G32B32A32_SFLOAT,
        gpu::ImageUsage::Storage,
        gpu::ImageType::Image2D, 1, 0, "RT accumulation image"
    });
    cleanup.push(newAccum);

    outputSet->cleanup();
    auto newOutputSet = device->createResourceSet(layout.get(), 0, "Output set");
    newOutputSet->setStorageImage({.vulkan = 0, .metal = 0}, newOutput.get());
    newOutputSet->setUniformBuffer({.vulkan = 1, .metal = 1}, cameraUbo.get());
    newOutputSet->setStorageImage({.vulkan = 2, .metal = 1}, newAccum.get());
    newOutputSet->update();
    cleanup.push(newOutputSet);

    outputImage = std::move(newOutput);
    accumImage  = std::move(newAccum);
    outputSet = std::move(newOutputSet);

    camData.misc.y = static_cast<float>(newWidth);
    camData.misc.z = static_cast<float>(newHeight);
    cameraUbo->updateUniformBuffer(camData);

    frameCount = 0;
}
```

On resize, the example:

1. Waits for the GPU to finish all work (`device->waitIdle()`)
2. Resizes the surface for the new dimensions
3. Destroys and recreates both the output and accumulation images at the new size
4. Destroys and recreates the output resource set with the new images
5. Updates the camera UBO with the new dimensions
6. Resets `frameCount` to 0 so the next frame writes directly to the uninitialized accumulation image

This is necessary because storage images cannot be resized in-place — they must be destroyed and recreated with new dimensions.

## Shader code explanation

### Ray generation shader (`ray_tracing_pipeline.rgen.glsl`)

```glsl
#version 460
#extension GL_EXT_ray_tracing : enable

layout(set = 0, binding = 0, rgba8)   uniform image2D outputImage;
layout(set = 0, binding = 2, rgba32f) uniform image2D accumImage;
layout(set = 0, binding = 1) uniform CameraData {
    mat4 viewInverse;
    mat4 projInverse;
    vec4 misc; // x=frameCount, y=width, z=height
} cam;
layout(set = 1, binding = 0) uniform accelerationStructureEXT tlas;

struct HitInfo {
    vec3  hitPos;
    vec3  normal;
    vec3  albedo;
    vec3  emission;
    float roughness;
    int   hit; // 1 = surface hit, 0 = ray escaped the scene
};
layout(location = 0) rayPayloadEXT HitInfo payload;

const int   MAX_BOUNCES = 8;
const float PI = 3.14159265359;
```

The ray generation shader declares the resource bindings matching the pipeline layout:

- **`outputImage`**: 8-bit storage image for the final tonemapped result
- **`accumImage`**: 32-bit float storage image for the progressive accumulation
- **`cam`**: camera UBO with inverse matrices and frame metadata
- **`tlas`**: the top-level acceleration structure
- **`payload`**: the ray payload struct shared between ray generation, miss, and closest hit shaders

The `HitInfo` struct is the ray payload — it carries surface information from the closest hit shader back to the ray generation shader.

#### Random number generation

```glsl
uint pcg(inout uint state) {
    state = state * 747796405u + 2891336453u;
    uint word = ((state >> ((state >> 28u) + 4u)) ^ state) * 277803737u;
    return (word >> 22u) ^ word;
}
float rnd(inout uint state) { return float(pcg(state)) / 4294967295.0; }
```

Path tracing requires random numbers for importance sampling. The PCG (Permuted Congruential Generator) hash is a fast, lightweight PRNG suitable for GPU shaders. Each pixel seeds its RNG with a value derived from its coordinates and the frame count, so different pixels and different frames produce different random sequences.

#### Cosine-weighted hemisphere sampling

```glsl
vec3 cosineHemisphere(vec3 n, inout uint state) {
    float r1 = rnd(state);
    float r2 = rnd(state);
    float phi = 2.0 * PI * r1;
    float r = sqrt(r2);
    vec3 up = abs(n.x) > 0.9 ? vec3(0.0, 1.0, 0.0) : vec3(1.0, 0.0, 0.0);
    vec3 tangent = normalize(cross(up, n));
    vec3 bitangent = cross(n, tangent);
    return normalize(tangent * (cos(phi) * r) +
                     bitangent * (sin(phi) * r) +
                     n * sqrt(1.0 - r2));
}
```

Cosine-weighted hemisphere sampling generates random directions biased toward the surface normal. This importance sampling technique reduces variance compared to uniform hemisphere sampling — more samples are generated in the direction that contributes most to the integral. The `up` vector selection avoids degenerate cross products when the normal is nearly aligned with the world X axis.

#### Camera ray generation and path tracing

```glsl
void main()
{
    uint seed = (gl_LaunchIDEXT.x * 1973u + gl_LaunchIDEXT.y * 9277u +
                 uint(cam.misc.x) * 26699u) | 1u;

    vec2 jitter = vec2(rnd(seed), rnd(seed));
    vec2 pixelCenter = vec2(gl_LaunchIDEXT.xy) + jitter;
    vec2 inUV = pixelCenter / vec2(cam.misc.y, cam.misc.z);
    vec2 d = inUV * 2.0 - 1.0;

    vec4 origin = cam.viewInverse * vec4(0, 0, 0, 1);
    vec4 target = cam.projInverse * vec4(d.x, -d.y, 1, 1);
    vec4 direction = cam.viewInverse * vec4(normalize(target.xyz), 0);

    vec3 rayO = origin.xyz;
    vec3 rayD = direction.xyz;
```

The camera ray is constructed by:

1. **Seeding the RNG** from pixel coordinates and frame count
2. **Sub-pixel jitter**: adding a random offset within the pixel for anti-aliasing (each frame samples a different sub-pixel position)
3. **UV mapping**: converting pixel coordinates to normalized device coordinates (-1 to 1)
4. **Ray reconstruction**: using the inverse projection and view matrices to convert the NDC point into a world-space ray origin and direction

The `target` is computed by applying the inverse projection to the NDC coordinate, and the inverse view transforms it to world space. The ray origin is always the camera position (the fourth row of the inverse view matrix).

#### Path tracing loop

```glsl
    vec3 radiance = vec3(0.0);
    vec3 throughput = vec3(1.0);

    for (int b = 0; b < MAX_BOUNCES; ++b)
    {
        traceRayEXT(tlas, gl_RayFlagsOpaqueEXT, 0xff,
            0, 0, 0,
            rayO, 0.001, rayD, 10000.0, 0);

        if (payload.hit == 0)
        {
            break;
        }

        radiance += throughput * payload.emission;

        vec3 n = payload.normal;
        vec3 refl = reflect(rayD, n);
        vec3 diff = cosineHemisphere(n, seed);
        vec3 newDir = normalize(mix(refl, diff, payload.roughness));
        if (dot(newDir, n) < 0.0)
        {
            newDir = diff;
        }

        throughput *= payload.albedo;
        rayO = payload.hitPos + n * 0.001;
        rayD = newDir;

        float maxThroughput = max(throughput.r, max(throughput.g, throughput.b));
        if (maxThroughput < 0.001)
        {
            break;
        }
    }
```

The path tracing loop implements a multi-bounce path tracer:

1. **Trace a ray** with `traceRayEXT()` using opaque flags (no any-hit shader)
2. **Check for miss**: if `payload.hit == 0`, the ray escaped the box — the Cornell box is closed, so this produces a black background
3. **Accumulate emission**: the surface's emission is multiplied by the current throughput (the accumulated reflectance along the path)
4. **Generate new direction**: the `roughness` parameter interpolates between a perfect mirror reflection (`reflect()`) and a diffuse cosine-weighted bounce (`cosineHemisphere()`). This is a simple glossy material model
5. **Update throughput**: multiply by the surface albedo (reflectance)
6. **Offset origin**: push the new ray origin slightly above the surface to prevent self-intersection
7. **Russian roulette termination**: paths with negligible throughput are terminated early

The `traceRayEXT()` call parameters:

| Parameter | Value | Meaning |
|-----------|-------|---------|
| `tlas` | bound TLAS | Acceleration structure to trace against |
| `gl_RayFlagsOpaqueEXT` | flags | Skip any-hit shaders, treat geometry as opaque |
| `0xff` | mask | Instance visibility mask |
| `0, 0, 0` | SBT offset, stride, index | Shader binding table indices (single closest hit shader) |
| `rayO` | origin | World-space ray origin |
| `0.001` | tMin | Minimum ray distance (skip self-intersection) |
| `rayD` | direction | Unit direction vector |
| `10000.0` | tMax | Maximum ray distance |
| `0` | payload location | Layout location of the payload |

#### Monte Carlo accumulation and tone mapping

```glsl
    float frameCount = cam.misc.x;
    vec3 prev = imageLoad(accumImage, ivec2(gl_LaunchIDEXT.xy)).rgb;
    vec3 accum = (frameCount <= 1.0) ? radiance
                                      : mix(prev, radiance, 1.0 / frameCount);
    imageStore(accumImage, ivec2(gl_LaunchIDEXT.xy), vec4(accum, 1.0));

    vec3 mapped = accum / (accum + vec3(1.0));
    mapped = pow(mapped, vec3(1.0 / 2.2));
    imageStore(outputImage, ivec2(gl_LaunchIDEXT.xy), vec4(mapped.bgr, 1.0));
}
```

The accumulation step computes a running mean:

- **Frame 1**: store the radiance directly
- **Frame N**: `mix(prev, radiance, 1/N)` — this is equivalent to `prev * (N-1)/N + radiance * 1/N`, the standard iterative formula for a running average

The tone mapping step converts HDR radiance to LDR:

1. **Reinhard tone mapping**: `mapped = accum / (accum + 1)` — compresses the HDR range to [0, 1)
2. **Gamma correction**: `pow(mapped, 1/2.2)` — converts from linear to sRGB color space
3. **Channel swizzle**: `mapped.bgr` — the output image is byte-copied into a BGRA8 swapchain, so blue and red must be swapped in the shader

### Miss shader (`ray_tracing_pipeline.rmiss.glsl`)

```glsl
#version 460
#extension GL_EXT_ray_tracing : enable

struct HitInfo {
    vec3  hitPos;
    vec3  normal;
    vec3  albedo;
    vec3  emission;
    float roughness;
    int   hit;
};
layout(location = 0) rayPayloadInEXT HitInfo payload;

void main()
{
    payload.hit = 0;
}
```

The miss shader is minimal — it sets `payload.hit = 0` to signal that the ray did not hit any geometry. The ray generation shader interprets this as a black background (the Cornell box is closed, so rays that escape produce no color).

The `HitInfo` struct must be declared identically in all three shader stages (ray generation, miss, closest hit) because they share the same payload via `layout(location = 0)`.

### Closest hit shader (`ray_tracing_pipeline.rchit.glsl`)

```glsl
#version 460
#extension GL_EXT_ray_tracing : enable

struct HitInfo {
    vec3  hitPos;
    vec3  normal;
    vec3  albedo;
    vec3  emission;
    float roughness;
    int   hit;
};
layout(location = 0) rayPayloadInEXT HitInfo payload;
hitAttributeEXT vec2 attribs;

struct InstanceData {
    vec4 albedo;
    vec4 emission;
    vec4 normalOrCenter;
    vec4 extents;
};
layout(set = 2, binding = 0) buffer InstanceBuffer { InstanceData data[]; } instances;

void main()
{
    InstanceData inst = instances.data[gl_InstanceCustomIndexEXT];
    int shapeType = int(inst.emission.a);

    vec3 worldPos = gl_WorldRayOriginEXT + gl_WorldRayDirectionEXT * gl_HitTEXT;
```

The closest hit shader:

1. **Reads instance data**: uses `gl_InstanceCustomIndexEXT` to index into the SSBO — this is the `instanceId` passed to `rayTracingScene->addInstance()`
2. **Extracts shape type**: from the `emission.a` component (packed in the CPU-side code)
3. **Computes world position**: reconstructs the hit position from the ray origin, direction, and hit distance

#### Analytic normal computation

```glsl
    vec3 n;
    if (shapeType == 0)        // plane
    {
        n = normalize(inst.normalOrCenter.xyz);
    }
    else if (shapeType == 1)   // sphere
    {
        n = normalize(worldPos - inst.normalOrCenter.xyz);
    }
    else                       // cube: dominant axis of the local position
    {
        vec3 local = (worldPos - inst.normalOrCenter.xyz) / max(inst.extents.xyz, vec3(1e-4));
        vec3 a = abs(local);
        if (a.x > a.y && a.x > a.z)      n = vec3(sign(local.x), 0.0, 0.0);
        else if (a.y > a.z)              n = vec3(0.0, sign(local.y), 0.0);
        else                             n = vec3(0.0, 0.0, sign(local.z));
    }
```

Surface normals are computed analytically based on the shape type:

- **Plane**: the normal is stored directly in `normalOrCenter.xyz` (the world-space normal passed from the CPU)
- **Sphere**: the normal is the vector from the sphere center to the hit point, normalized
- **Cube**: the normal is determined by the dominant axis of the local position (divided by half-extents). The axis with the largest absolute component indicates which face was hit

#### Two-sided normal handling

```glsl
    if (dot(n, gl_WorldRayDirectionEXT) > 0.0)
    {
        n = -n;
    }

    payload.hitPos    = worldPos;
    payload.normal    = n;
    payload.albedo    = inst.albedo.rgb;
    payload.emission  = inst.emission.rgb;
    payload.roughness = inst.albedo.a;
    payload.hit       = 1;
}
```

The normal is flipped to face the incoming ray direction. This makes surfaces two-sided — a ray can hit either side of a plane. Without this, rays hitting the back face of the ceiling light would produce incorrect shading.

The payload is filled with the surface data and `hit = 1` signals a successful intersection.

## Key concepts

### Progressive accumulation

The path tracer produces one noisy sample per pixel per frame. Over many frames, the samples converge to the correct result through Monte Carlo averaging:

```
Frame 1:   noisy image (variance high)
Frame 10:  less noisy (variance decreasing)
Frame 100: smooth (variance low)
Frame N:   convergence (variance → 0)
```

The accumulation formula is:

```
accum_N = accum_{N-1} * (N-1)/N + radiance * 1/N
```

This is computed incrementally with `mix(prev, radiance, 1/N)`. The `frameCount` must be reset to 0 whenever the accumulated result becomes invalid — otherwise the old frames dominate the average and changes produce no visible effect.

### Dual-image output strategy

The two-image approach is necessary because:

- **Accumulation** requires floating-point precision (`R32G32B32A32_SFLOAT`) to store the running average without quantization artifacts
- **Swapchain copy** requires an 8-bit format (`R8G8B8A8_UNORM`) for direct byte-copy compatibility

The shader writes the tonemapped result to the 8-bit image while storing the linear HDR result in the float image. This avoids the precision loss that would occur if the accumulation were done in 8-bit.

### Glossy material model

The roughness parameter interpolates between two BRDF lobes:

```glsl
vec3 refl = reflect(rayD, n);
vec3 diff = cosineHemisphere(n, seed);
vec3 newDir = normalize(mix(refl, diff, payload.roughness));
```

- **roughness = 0**: perfect mirror reflection (all samples in the reflection direction)
- **roughness = 1**: diffuse Lambertian (cosine-weighted random direction)
- **0 < roughness < 1**: glossy blend between mirror and diffuse

This is a simplified material model. A production renderer would use a physically-based BRDF (e.g., GGX) with proper PDF and multiple importance sampling.

### Analytic normals vs. geometry normals

The closest hit shader computes normals analytically rather than interpolating per-vertex normals. This is possible because the Cornell box scene uses simple shapes (planes, sphere, axis-aligned cube). The advantages:

- No per-vertex normal data needed in the mesh
- Exact normals (no interpolation artifacts)
- The same `MeshPN` format is used, but the normal attribute in the vertex data is ignored

For complex geometry, you would use `hitAttributeEXT` to interpolate barycentric coordinates and fetch per-vertex normals from a buffer.

### Resource set update without re-calling update()

The camera UBO is updated each frame:

```cpp
cameraUbo->updateUniformBuffer(camData);
```

This only updates the buffer contents — the resource set does not need to be re-created or re-updated. The descriptor still points to the same buffer, and the new data is visible to the shader on the next dispatch.

### Cleanup pattern

All resources are tracked in a `CleanupManager` and released in reverse order. The example also explicitly cleans up `RayTracingMesh` objects and meshes before flushing the cleanup manager:

```cpp
device->waitIdle();
for (auto& piece : pieces)
{
    for (auto& rtMesh : piece->rtMeshes) { rtMesh->cleanup(); }
    piece->mesh->cleanup();
}
pieces.clear();
cleanup.flush();
surface->cleanup();
device->cleanup();
instance->cleanup();
```

Explicit cleanup is needed for resources that are not pushed to the `CleanupManager` (like individual meshes and RT meshes within pieces). The `device->waitIdle()` call ensures all GPU work is complete before destroying resources.
