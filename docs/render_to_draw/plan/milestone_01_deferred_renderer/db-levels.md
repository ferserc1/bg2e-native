# M01-07 DB representation and resource loading

## Two explicit IO levels

`db::readSceneDocument(path)` and `writeSceneDocument(document, path)` read/write JSON scene documents. They require a scene array, validate a supplied file type, preserve unknown JSON fields/component representations and never inspect referenced assets. Missing files, malformed documents and write/close failures throw. These functions do not instantiate components or export resources. Use this level to edit documents whose custom component implementations are unavailable.

`db::loadScene(path)` builds a `scene::Scene` with CPU component attributes and unresolved resource references. Its base-path/name overload has the same behavior. `Component::deserialize(data, basePath)`, `Component::serializeReferences(basePath)`, `Node::deserialize(data, basePath, progress)` and `Node::serializeReferences(basePath, progress)` provide the corresponding graph contracts. `Scene::deserialize(data, basePath, progress)` adds the existing synthetic scene root around document nodes. A typed graph models the supported schema; it is not a lossless container for arbitrary JSON extensions. Use document IO for those extensions.

`db::saveSceneReferences(root, path, progressCallback)` writes that graph representation explicitly. It neither exports meshes nor copies images, and never claims to save pending material/geometry edits, GPU-authored textures or asset contents. References may point at nonexistent files. Serialization rebases source paths lexically against the output directory without requiring assets to exist. The caller chooses the node being written; passing the synthetic scene root writes it as another document node, matching the existing root-based writer convention.

## Built-in component contracts

Camera, light, transform, orbit-camera, chain/joint and polar/fixed-scale controller parsers now have engine-free overloads, with the existing production overloads delegating to them. Their reference serialization uses their existing pure attribute serializers. Priority is restored through the common CPU parser.

EnvironmentComponent's engine-free parser retains its equirectangular source reference; reference serialization emits a relative/absolute path without copying/opening the image. Production's progress-aware overload still performs its original production cache load. M01-08 now supplies explicit EnvironmentGenerator synchronization of this source outside active recording; the DB loader itself keeps the source declarative and never initializes a production texture cache for draw.

DrawableComponent's engine-free parser accepts explicit `path` or legacy `name` (resolved as `.bg2`). `resourcePath()` stores the lexically normalized absolute source path; `setResourcePath(path)` records an explicit source without replacing any live drawable. It must not be read into a populated component without clearing that component. Empty/missing references fail. An unresolved component has execution mode Uninitialized and no CPU mesh or GPU resources. Clone preserves its reference independently. clearDrawable releases the live connector while retaining its source reference for later realization; setResourcePath({}) clears that reference explicitly. Reference serialization needs a source path, including for programmatically constructed drawables; a display name is not a fabricated asset file. Source references identify input assets and do not represent a snapshot of live edits.

Existing production DrawableComponent loading accepts both legacy names and explicit BG2/OBJ paths, using the same CPU reference decoder before its original production loaders. Production scene load/save conveniences remain available. A complete save of an unresolved or draw drawable is explicitly rejected; callers must deliberately select `saveSceneReferences` for metadata/reference IO. Full draw export remains M06/M07.

## Engine-aware realization

`db::loadScene(path, draw::Engine&, callback)` parses the graph, then calls `Node::loadResources(engine, progress)` recursively. The base-path/name overload uses the same route. `Scene::deserialize` and `Node::deserialize` also have draw Engine reference overloads. These paths never construct a production Engine or invoke production component creators. Errors propagate to the caller rather than reporting a successful graph with silently skipped resources/components. Progress counts graph nodes and file texture slots; draw environment preparation has no image event yet.

The separate `loadResources` hook also allows `db::loadScene(path)` first and realization later, after assets become available. DrawableComponent loads BG2/OBJ through the supplied draw Engine. An existing unloaded draw drawable is realized, an existing loaded drawable on the same Engine is retained, and production-mode or other-context components fail. All callers stop frame/background producers and keep the Engine alive until every graph/resource owner is released. Explicit realization on an existing graph can make partial progress before an exception; release or repair that graph before retrying. High-level load does not publish its graph when realization fails.

`db::loadDrawableBg2(path, draw::Engine&, onTextureLoaded)` and its base-path/name overload reuse `loadMeshBg2`: CPU mesh/material parsing, independent draw material settings, submesh names/groups/visibility and normal draw GPU realization. `loadDrawableObj(path, draw::Engine&)` and its base-path/name overload reuse the standard CPU OBJ parser and tangent generator. OBJ is currently geometry only; MTL/material import remains future work. Missing OBJ normals generate per-triangle normals and missing UVs use zero; malformed indices/parser failures are rejected. Standard PNUUT allocation now unwinds safely on parser failure. Existing render Engine pointer overloads remain distinct, including calls with null pointers; draw overloads use references.

## Custom component registration

The existing production `Creator`/`DefaultCreator` registration and macro remain source compatible. New `ComponentFactoryRegistry::create(data, basePath)` uses the registered DefaultCreator, then invokes the engine-free virtual parser on a Component pointer. The draw Engine overload follows that with `loadResources`. Unknown/malformed component types, null constructors and missing schema implementations throw. They never fall back to the production Creator or silently discard the component.

Custom components implement the new two-argument `deserialize`, `serializeReferences` and, when needed, `loadResources(draw::Engine&, SceneLoadProgress*)`. The base schema/parser and reference serializer throw until implemented; the default resource hook does nothing. Subclasses of built-in components must extend the inherited schema methods to retain their own fields. A custom factory whose construction requires production state must supply a genuinely engine-free DefaultCreator for the new route. Keep the old production parser/Creator for production use. Raw document IO remains the option for unknown/custom schemas; no placeholder compatibility architecture is added.

## Save and future resource IO responsibilities

M06-02/M07-02 must provide a complete engine-aware draw save: synchronize producers, capture live CPU/material state, read back GPU-only/edited images (including authored subresources), encode/copy actual assets, preserve color/sampler/UV/lightmap/joint metadata and publish references only after resource writes succeed. Reference IO alone is not sufficient, even when all source paths happen to exist. glTF/MTL import and complete export remain scheduled rather than partially implemented here. M08-02 consumes those complete paths.
