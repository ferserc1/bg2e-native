# Draw geometry, material and texture resources (M01-06)

## Drawable connector

`draw::Drawable` owns a `geo::MeshPNUUT` CPU mesh, per-submesh material/transform/name/group/visibility metadata, a `gpu::MeshPNUUT` raster realization, six-channel `draw::MaterialBase` objects and optional built `gpu::RayTracingMesh` objects. This is the same standard two-UV/tangent layout as scene::Mesh. Production's additional generic Drawable specializations remain untouched; this new connector currently supplies the standard engine layout only. No external realization registry, ResourceManager, per-frame mesh ring or native Vulkan handle is introduced.

`setMesh`, `mesh`, `material`, submesh metadata accessors, `load`, `reload`, `updateMaterials`, `applyModifier`, `drawMesh`, `drawMaterial`, `rayTracingMeshes` and `cleanup` provide ordinary connector operations. Bad indices throw. Empty/invalid indices and non-triangle submesh ranges are rejected; an otherwise valid mesh with no submesh table receives one full-range submesh. Changing submesh topology uses setMesh; in-place vertex/index edits use reload. Metadata is retained by submesh index during setMesh; new indices receive defaults.

After loading, material(index) exposes the live MaterialBase attributes. Submesh metadata stays on Drawable. Whole/local submesh transforms remain distinct. `draw(frame, bind)` and `drawSubmesh(frame, index, bind)` validate the frame Engine, honor submesh/material visibility, bind the raster buffers, invoke the application's explicit material/transform/submesh binding callback and issue indexed drawing. The callback does not infer pipeline descriptors or shader ABI. M01-09/10 own those bindings and graph/scene scheduling.

Load/reload/rebuild operations are synchronous rare-edit operations that wait for users. Callers stop frame/background/native producers throughout them; a wait does not prevent a later racing submitter. Reload recreates raster/tracing geometry and applies pending texture edits while preserving existing material realizations, including GPU-authored textures. It does not automatically reread every file texture; Texture::reload does that explicitly. Scalar material edits need no texture reload. After a realization failure, isLoaded is false and drawing/cloning an incomplete realization is rejected; callers can fix/retry or clean it up. CPU edits awaiting reload remain explicit and must not be used to assume the GPU snapshot already changed.

## Material and texture state

`draw::MaterialBase` owns live base::MaterialAttributes and six stable texture realizations: albedo, metalness, roughness, normal, AO and light emission. All existing attribute values survive value copying, including alpha/transparent/solid/unlit/refraction, Fresnel/sheen, per-channel inversion/scales/channels/UV sets, metadata and visibility. White defaults and a neutral normal texture are independent per material. Flags describe pending realization updates; updateTextures realizes changed channels and marks them updated. Direct edits to a base::Texture descriptor must be followed by its material texture setter (to invalidate that slot), or an explicit texture reload/updateSampler. Setting a new MaterialAttributes value also detects changed texture descriptor pointers.

`setTexture(slot, drawTexture)` installs a GPU-authored realization with same-Engine/device validation and records independent source/sampler settings. Ordinary loading is uncached by default. Explicit useTextureCache can share immutable filesystem inputs; cloning always bypasses it. Materials, textures and drawables disable implicit copy construction/assignment, using explicit clone instead.

`draw::Texture` loads filesystem, procedural and supplied CPU images or adopts a shared generic GPU image with sampled usage and device checks. SDR uses RGBA8 UNORM; HDR uses RGBA32 float. Color-space metadata is preserved separately, matching the production manual shader-conversion convention: M01-10 must interpret it explicitly rather than silently switch to an sRGB allocation. Requested linear filtering and multi-level generation are capability-checked and fail clearly if unavailable; callers choose any fallback. One-level textures do not require a mip-generation capability. Uploaded CPU data initializes mip zero and generates the requested chain explicitly. In-memory SDR/HDR pixels retain an independent CPU snapshot for reload; adopted GPU-only images without a source have no invented reload source. Their exact contents remain cloneable through transfers.

Sampler settings preserve min/mag/mip filtering, U/V/W addressing, LOD interval and bias. The interval is clamped to the allocated levels (or zero when mipmaps are disabled). GPU SamplerDescription appends mipLodBias and AddressMode appends ClampToBorder; native Vulkan/Metal map them directly, with opaque-black borders. Metal checks runtime support before using the LOD-bias selector: unavailable nonzero bias fails explicitly, while zero remains usable on older runtimes. Native device sampler limits still apply.

## Independent cloning

Drawable::clone deep-copies CPU vectors and metadata, then independently builds raster buffers from the source's actual uploaded mesh snapshot. CPU edits awaiting reload stay pending in the copied CPU mesh, rather than being incorrectly treated as already uploaded geometry. Live material attributes and their texture descriptors are deep-copied. Procedural descriptors become private pixel snapshots because arbitrary ProceduralTextureGenerator subclasses have no cloning API and may contain mutable state. Snapshotting evaluates generate; applications must supply a valid generator, not race its state while cloning.

Loaded MaterialBase clones allocate a new object and clone every realized texture/sampler, retaining pending update flags. Texture::clone allocates the same format/type/levels/usages and copies each mip/layer through public GPU subresource commands. It preserves the source's prior layout for each subresource and leaves the destination shader-readable. Authored levels are copied, not regenerated. Transfer-source usage and defined source subresources are required and validated before recording; every engine-created draw texture has transfer usages. CPU reload snapshots are also independent. GPU-only texture clones never route through a filesystem/cache reload. The engine/device is retained only as a borrowed context; all these resources must be released before context teardown.

When the source has built tracing geometry, clone rebuilds it against the clone's raster buffers even if future tracing was subsequently disabled. An unsupported device simply has no tracing realization. Tracing structures are released before the raster buffers they borrow. Changing the enable flag takes effect on geometry reload. BLAS lifetime/instance transform updates in future query/RT scenes remain with their users.

## Shared scene and cache coexistence

DrawableComponent adds typed shared/raw draw constructors, setDrawable(drawable), drawDrawable, executionMode and clearDrawable. Modes are Uninitialized, Production or Draw, selected by its retained type, independently of whether that drawable already has GPU resources. Legacy drawable/drawableBase access on a draw component and drawDrawable access on a production component throw explicitly. Cross-mode setter access also throws; clear the component at a coordinated boundary first. Replacing loaded draw contexts requires clearing first. Draw setters/clear wait for the current draw device; legacy owners retain their existing safe-update synchronization requirement. Clearing releases this component's references, not other owners' resources. Component cloning uses the matching deep clone; Node cloning inherits it.

Shared BoundingBox handles both modes explicitly, including draw whole/local transforms and visibility. OrbitCameraComponent supports the draw path for its existing centering behavior. Production rendering visitors still use their typed production accessor; supplying draw resources to that execution reports the mode error instead of silently casting. M01-09 adds the actual draw visitors. M01-07 now supplies explicit graphics-free reference serialization and draw-aware loading; see [db-levels.md](db-levels.md). Complete resource export still fails explicitly until M06/M07; it never silently writes an empty component.

TextureCache adds matching draw load overloads in separate weak storage. Keys include device identity, normalized absolute file path and exact sampler/color settings (float bit identities, including bias). Cache hits recheck Engine/device and current settings. Weak entries do not extend native lifetime; no global default draw texture pins an Engine. Engine/device must outlive all external realizations. Cache clients treat shared inputs as immutable; direct pixel mutation of explicitly shared inputs is intentionally shared, whereas clone always owns new resources. Production cache storage remains separate and its existing behavior is preserved.

The existing db::loadImage handed STB allocations directly to base::Image, whose destructor uses delete[]. The image-loader boundary now copies decoded SDR/HDR pixels into new[] storage and frees the decoder allocation with stbi_image_free. This narrow ownership correction is required by ordinary draw texture loading/reloading and leaves decoding values/API unchanged; it does not implement M01-07 serialization early.
