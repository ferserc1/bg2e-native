# M01-08 public environment tools

## Public API and ownership

`draw::environment::SphereToCubemapRenderer`, `ProceduralSkyRenderer`, `IrradianceCubemapRenderer`, `SpecularReflectionCubemapRenderer` and `BRDFIntegrationMapTextureGenerator` are standalone public services derived from `CubemapRenderer`/`EnvironmentPass`. `generate(Engine&, shared_ptr<gpu::Image> source)` completes synchronous GPU work and returns a shared image. Sphere conversion requires a linear floating-point 2D source; irradiance/specular require a cubemap; procedural sky/BRDF need no source. The source must belong to the same device, have Sampled usage and every subresource in ShaderReadOnly. HDR formats are RGBA16F/RGBA32F. Unsupported target usages fail explicitly; RT support is irrelevant.

`GenerationSettings` exposes square extent, explicit/full-chain mip count, sample count (1–4096), format, deployed engine shader root and vertex/fragment shader identities. Defaults are sky/specular 256 with full mip chains, irradiance 32 and BRDF 128 with one level, using 256 samples. Specular requires at least two levels so its roughness endpoints are defined. Settings are snapshotted during initialize/generate; changing them requires a rebuild at a stopped-producer boundary. Compatible application subclasses may override generation/recording and shaders. They must preserve the `draw.environment.<semantic>.v1` contracts and allocate fresh outputs rather than modify previously published snapshots.

`initialize` allocates but does not record. `setSource` requires a cleaned-up pass. `record(PassContext)` generates into internally owned targets; optional output binding must identify that exact image and semantic. Inputs come from setSource, not PassContext. Empty or matching output contract metadata is accepted; external replacement targets are rejected. `resize` reallocates using current GenerationSettings, followed by record/generate before sampling. `attachScene`/`update` are no-ops because these tools own no graph. Individual pass `resources()` contains only its generated semantic, not a complete validated IBL set.

`EnvironmentGenerator(engine, shaderRoot)` supplies normal tool objects through its mutable `EnvironmentGenerationConfiguration`. `build(hdrPath)` loads HDR pixels, uploads a linear RGBA16F source and generates sky/irradiance/specular/BRDF. Empty path deliberately selects procedural sky. SDR files, missing files, incompatible shaders/resources or unsupported usages throw; they do not silently substitute another source. `build(shared_ptr<Image>)` accepts an explicitly linear HDR source; a null image is rejected. Source mip generation is capability-checked; unsupported generation uses one source level. Sampling uses nearest filtering when linear filtering is unavailable.

The generator publishes a `shared_ptr<const EnvironmentResources>` only after all generation and validation complete. Default tools allocate new images, preserving old published resources on failure. Consumers retain snapshots, rebind on replacement and release all owners before Engine/device teardown. `cleanup()` waits and releases this service's references; externally retained snapshots remain usable. No global resource cache pins an Engine. Explicit lifecycle/source/replacement calls require producers stopped and no active frame/command recording; do not call synchronous generation from renderer record/update inside an acquired frame.

## Scene intent and renderer handoff

EnvironmentComponent retains `environmentImage` and adds `setSkyboxBlur(float)`/`skyboxBlur()` in [0,1], plus `setSkyboxVisible(bool)`/`skyboxVisible()`. Both attributes serialize through pure reference IO and the legacy serializer. No GPU bindings/resources are stored in scene.

`EnvironmentGenerator::synchronize(component)` compares source paths, builds the new environment when needed and applies blur/visibility to a new immutable snapshot. A null component/empty source selects default sky. Blur/visibility changes share existing images; unchanged state returns false. Explicit build reloads the same path after file/configuration edits. This step exposes the safe operation; M01-10 wires it into the deferred renderer's attach/safe-update boundary. It must never perform upload/wait/submission inside the renderer's active recording path. After synchronization, rebind both skybox and lighting consumers to the published snapshot.

`EnvironmentResources` retains `sky`, `irradiance`, `prefilteredSpecular`, `brdf`, shared cube `sampler`, separate `brdfSampler`, blur and visibility. `validate(Device*)` checks full set readiness, types, mip requirements, contexts and all ShaderReadOnly states. Sky/irradiance/specular use clamp-to-edge, compatible linear/nearest filtering and exposed LOD; BRDF uses clamp-to-edge and LOD 0. No native descriptors appear in draw/scene public contracts.

## Shader/resource ABI

Paired stages live under `shaders/src/draw/environment/` and are discovered/deployed by the existing recursive build integration. No CMake change was made. Vulkan entries are main; Metal uses vertMain/fragMain.

- Fullscreen vertex has no buffers or attributes and emits far depth 1. Generation uses fragment push data of 32 bytes: four uints (face, destination size, samples, source width), four floats (roughness/mip parameter, source max LOD, two padding values). Source images use Vulkan set 0/binding 0 and sampler binding 1; Metal texture 0/sampler 0, push buffer 0. Procedural sky/BRDF have no sampled resources.
- Face order is +X, -X, +Y, -Y, +Z, -Z. Fragment pixel coordinates reconstruct the native cubemap sampling directions; CubemapRenderPass drives attachments/mips but its camera matrices are unused. Equirectangular UV uses atan(z,x)/(2 PI)+0.5 and acos(y)/PI for unflipped top-row-first HDR pixels. Both languages implement the same mapping and algorithms.
- Irradiance is the cosine-weighted hemisphere integral, including PI. Lighting consumes albedo * irradiance / PI, with material/occlusion policy supplied by the later lighting pass.
- Prefilter uses GGX importance sampling and source-mip solid-angle selection. Destination mip `m` encodes perceptual roughness `m/(levels-1)`; roughness 0 samples sharp radiance. Every level/face is rendered independently. Never regenerate this authored mip chain. Blur samples this same chain at normalized blur * (levels-1).
- BRDF LUT is RG = split-sum A/B, sampled at (NdotV, perceptual roughness). Specular composition uses F0 * A + B. BA are 0/1. Outputs are linear, not sRGB, and contain no tone mapping/exposure baked into IBL.

## Skybox renderer

`SkyboxRenderer` implements `SkyboxPass`, retains an environment snapshot and exposes shader settings plus live exposure in stops. `setCamera(view, projection)` removes camera translation and stores inverse rotation/projection. `initialize(engine, colorFormat, depthFormat)` supports standalone use; `draw(command, extent)` records inside a compatible existing rendering scope. With depth, fullscreen far-depth LessOrEqual never writes depth and preserves foreground geometry. Without depth, draw before foreground geometry.

The RenderLayer initializer uses contract outputs named color and optional depth. Its record validates/loads initialized matching single-sample images, begins its own rendering scope, draws and restores color mip 0 to ShaderReadOnly; depth remains DepthAttachment. Color needs ColorAttachment and Sampled usages. Environment inputs are retained by setEnvironment, not transient PassContext inputs. Sky replacement rebinds immutable sets after waiting. Camera/exposure are pushed per draw; there are no overwritten per-frame UBOs. Resize recreates format-dependent pipeline/bindings while retaining generated IBL resolutions/resources. Exposure scales linear sky radiance by exp2; tone mapping/output transfer belongs to later final processing.

## Integration and verification

Example 06 now calls EnvironmentGenerator and SkyboxRenderer; its reflective cube still selects original/irradiance/specular maps and inspects authored LOD. Generation no longer lives inside the application. Existing example shader assets remain available as historical references, but its generation uses deployed engine shaders.

Agent checks were static only: declarations/call sites, source/target ownership, failure publication, native binding/packing, shader pairing/entry points/includes, six-face coordinate formulas, mip/roughness ordering, dependency boundaries, documentation links and git diff --check. No build/configuration/shader compilation or runtime execution.

The [manual probe](../../../../tests/draw/environment/README.md) checks constant radiance/PI normalization on all faces/mips, finite BRDF, missing HDR replacement, default sky, immutable blur/visibility snapshots and retained resource lifetime. Lead validation also covers example 06, asymmetric HDR axes/seams, skybox depth occlusion/rotation, resize, source/blur switching, unsupported configurations and available Vulkan/Metal with RT disabled. Actual backend/runtime evidence remains pending.
