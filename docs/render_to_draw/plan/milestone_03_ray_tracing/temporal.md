# M03-07 implementation handoff

## Borrowed public inputs and chronology

TemporalAccumulator, TemporalConfiguration/Settings/Input/Result, TemporalSignal/Key and TemporalView are implemented in draw::pipeline. Input exposes signal, SurfaceInputs, current unjittered view/projection and jitteredProjection, external generation, rendered scene sequence, presentation serial and retired slot. Reflections additionally supply receiver roughness and maxRoughness. Consumers do not reach private renderer targets. Key is (kind,view,layer); scalar AO, diffuse HDR and reflected HDR never share history. The renderer uses view zero, opaque layer zero and packed extraction objectId/submesh for transparent layers. The exact node/submesh/resource extraction signature resets all correspondence when identities or topology change; duplicate/empty persistent node/submesh identities are diagnosed when histories are active.

beginFrame is called only for actual scene work, once per acquired serial, and clears only the completed slot's owners. sceneFrameNumber is nondecreasing across a lifecycle. A key must be recorded once per scene sequence; nonconsecutive key sequences reset it. UI-only presentations, pause, pick and overlay work do not record histories. Missing keys older than the preceding rendered scene are pruned; maxHistories bounds the retained map. Explicit invalidation clears logical history but retains in-flight slot owners. Recording is provisional until successful ordered submission; invalidate after any abandoned/failed recording, including later layer/upscaler failures. Standalone clients must submit on the same ordered Device queue before recording successors; no cross-queue timeline/fence inference is introduced.

## Completion and data ownership

Each invocation creates new signal/position/normal images, retains the previous and next History plus immutable descriptors/uniforms in its acquired slot, and publishes the new latest History. Images are not overwritten while prior submissions can read them. Position is RGBA32 float (world XYZ, coverage W), normal is RGBA16 float (signed world XYZ, per-pixel accepted count W); output is sampled/storage/readback R16 or RGBA16. History count is bounded to 1024, exactly representable in half. The implementation favors explicit lifetime safety over an image pool: three images per active signal/layer invocation plus retained in-flight versions. Mesh/texture assets are not copied into frame rings. No per-frame waitIdle is added; cleanup drains at a stopped boundary.

TemporalResult owns the new sampled signal or returns borrowed input for disabled/unavailable pass-through. Caller retains input signal/surface/material through completion. A result owner can outlive logical reset/cleanup, but Device must outlive every returned owner. Non-RT use is supported. Required scalar/HDR/position storage/readback format failure or shader initialization failure leaves a diagnostic status and allocates no history images; RendererDeferred continues raw lighting. Initialization uses tiny zero sampled position/normal fallbacks so an absent history never aliases an output storage image through a sampled descriptor.

## Native shaders and rejection

Four native shader profiles (camera/world, scalar/HDR) have explicit Vulkan/Metal implementations. Set0 binding/native map: UBO0/buffer1; normal1/texture0; depth-position2/texture1; coverage3/texture2; current4/texture3; previous5/texture4; previous position6/texture5; previous normal7/texture6; material8/texture7; nearest sampler9/native0; output10/texture8; position output11/texture9; normal/count output12/texture10. Scalar output is r16f; HDR rgba16f. TemporalUniforms is 208 bytes: inverseVP0, previous jittered VP64, rejection128, kind/frame-limit/freeze/profile144, source/output extents160, camera position/maxRoughness176, reprojection flags192. Compute groups are 16x16. No CMake or GPU primitive changes are required.

Receiver mapping follows the existing effect profiles and nearest signal/source pixel centers. Camera positions reconstruct from current jittered inverse VP and map into previous jittered VP, using framebuffer Y opposite NDC Y. Reprojection checks clip W/depth/UV bounds, previous coverage, world-position distance and world-normal cosine. The distance threshold is absolute + relative*distance(currentWorld,currentCamera). Projection/profile/extent/roughness threshold/reset/scene-generation changes restart histories. Stationary explicit surfaces can use same-UV correspondence; this does not create a UV bake accumulator.

MotionVectorGenerator is the public CPU camera-motion reference: current/previous unjittered clip transforms from current jittered clip and previous-minus-current framebuffer pixels. Jitter-only changes yield zero unjittered motion. The temporal kernel uses previous jittered projection for actual history lookup; the existing FSR camera-motion texture generation and SDK jitter sequencing remain intact. There are no previous-object vectors: object/mesh/transform changes conservatively invalidate effects and SDK history, so moving-object correspondence is an explicit future expansion rather than silently using camera-only vectors on moved geometry.

## Signal math and bounds

Visibility averages scalar [0,1], uncovered=1. Diffuse radiance uses valid RGB and alpha one; current invalid GI clears pixel correspondence and leaves IBL fallback. Reflected radiance is confidence-weighted RGB with confidence averaged independently, returned unpremultiplied; eligible zero-confidence misses can converge with hits. Reflection roughness rejection/coverage clears the history and cannot revive old hits. Nonfinite current data produces the appropriate neutral signal. Valid black remains valid.

Accepted samples before maxFrames use arithmetic mean; count saturates at the bound. Rolling mode uses 1/maxFrames thereafter. Freeze mode reuses a valid accepted history at the bound, while rejection/invalid pixels still restart. Public frameCount is nominal consecutive view/effect/layer count, not a claim that every pixel reached the bound. New view/layer/effect, sequence gaps, generation changes and parameter changes reset correspondence. M04 bake exact averages and M05 requested rendered-frame scheduling remain distinct contracts.

## Renderer invalidation and integration

RendererConfiguration appends shared temporal injection; null constructs enabled defaults (32 frames, rolling, maxHistories256). RendererDeferred exposes temporal()/historyGeneration() and overrides generic Renderer::invalidateHistories(). resetUpscaler now forwards to this hook, preserving existing material editor/viewpoint application adapters while resetting both effects and SDK. Scene/extent/explicit camera/inspector/environment lifecycle paths reset it; renderer replacement starts a clean component lifecycle.

Before jitter preparation, the renderer compares exact initialized extraction/settings bytes, not a lossy hash or padded settings struct. It includes node/submesh identity and extraction IDs, mesh/BLAS/material/image/sampler identities, world transforms, complete MaterialData, lights, environment resources/options, camera identity/projection, extents, upscaler identity/requirements, mode/effect/noise/temporal/shadow controls. Changes increment the public renderer history generation and clear histories before fresh tracing snapshots are prepared. Existing effect preparation already rebuilds current transforms/materials/TLAS from that same queue. No immutable source mesh is updated through an in-flight ring.

Continuous scene-camera movement can reproject; camera identity/projection changes reset. A same-camera teleport must call invalidateHistories, as must in-place image content uploads and custom resource/shader changes that preserve identity. The application owns drained mutation boundaries, redraw and partial-failure notification; generic MaterialModifier/DrawMaterialEditor gain no history ownership. This explicit hook is the real reset entry, not FSR context state masquerading as effect history.
