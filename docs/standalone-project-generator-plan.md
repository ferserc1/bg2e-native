# Plan: Standalone Project Generator for bg2e

## Objective

Create a script system that generates a standalone CMake project outside the bg2e-native repository, using **pre-compiled libraries** (headers + binaries). The script must work on Windows (`.bat`) and macOS/Linux (bash).

The template application is based on `examples/12_scene_renderer`, which demonstrates:
- Scene graph with nodes, components, transforms, camera
- OBJ model loading with PBR materials
- Environment map (IBL) with skybox
- ImGui UI integration
- Custom component (`RotateCameraComponent`)

## Implementation Details

### Step 1: Create `cmake/standalone_utils.cmake`

**New file** — does NOT modify existing `cmake/utils.cmake`.

Contains:
- **Copied functions** from `cmake/utils.cmake` (unchanged):
  - `compile_shaders()` — for app-specific shaders
  - `build_shaders()`
  - `bundle_lib()` — macOS only
  - `bundle_libs()` — macOS only
  - `bundle_resources()`
  - `copy_vulkan_resources()` — macOS only

- **New function** `standalone_bundle_app()`:
  - Replaces `bundle_app()` for standalone projects
  - Links against pre-configured imported target `bg2e` (set up by root CMakeLists.txt)
  - Uses `${CMAKE_SOURCE_DIR}/include` for engine headers
  - Uses `${CMAKE_SOURCE_DIR}/shaders` for engine shaders
  - Uses `${CMAKE_SOURCE_DIR}/assets` for assets
  - Linux: sets RPATH to `$ORIGIN` so `libbg2e.so` is found alongside the executable (copied at build time)
  - Windows: copies `bg2e.dll` to output directory
  - macOS: bundles dylibs into `.app/Contents/lib/`

### Step 2: Create template root `CMakeLists.txt`

Generated by the script into `<target>/CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.18)
project(${PROJECT_NAME})

set(CMAKE_CXX_STANDARD 20)

list(APPEND CMAKE_MODULE_PATH "${CMAKE_SOURCE_DIR}/cmake")
find_package(SDL2 REQUIRED)
find_package(Vulkan REQUIRED)

# Import pre-compiled bg2e library
add_library(bg2e SHARED IMPORTED)
if(WIN32)
    set_target_properties(bg2e PROPERTIES
        IMPORTED_LOCATION "${CMAKE_SOURCE_DIR}/lib/windows/bg2e.dll"
        IMPORTED_IMPLIB "${CMAKE_SOURCE_DIR}/lib/windows/bg2e.lib"
    )
elseif(APPLE)
    set_target_properties(bg2e PROPERTIES
        IMPORTED_LOCATION "${CMAKE_SOURCE_DIR}/lib/macos/libbg2e.dylib"
    )
else()
    set_target_properties(bg2e PROPERTIES
        IMPORTED_LOCATION "${CMAKE_SOURCE_DIR}/lib/linux/libbg2e.so"
    )
endif()

include("${CMAKE_SOURCE_DIR}/cmake/standalone_utils.cmake")
add_subdirectory(app)
```

### Step 3: Create template `app/CMakeLists.txt`

```cmake
cmake_minimum_required(VERSION 3.18)
set(APP_TARGET_NAME ${PROJECT_NAME})
standalone_bundle_app(TARGET_NAME ${APP_TARGET_NAME})
```

### Step 4: Create template `app/main.cpp`

Based on `examples/12_scene_renderer/src/main.cpp` (142 lines). Includes:
- `RotateCameraComponent` custom component
- `BasicSceneDelegate` implementing all three delegate interfaces
- Scene graph: environment, 2 OBJ models, orbiting camera
- ImGui window with skybox toggle

Uses these assets: `two_submeshes.obj`, `two_submeshes_inner_albedo.jpg`, `two_submeshes_outer_albedo.jpg`, `country_field_sun.jpg`.

### Step 5: Create bash script (`scripts/create_standalone_project.sh`)

**Parameters:**
- `$1` (required): Target directory path
- `$2` (optional): Project name (default: `bg2e_app`)

**Validation:**
- Detects bg2e-native repository root (from script location via `$SCRIPT_DIR/..`)
- Checks target directory does not already exist
- Checks `bin/<platform>/` contains the pre-compiled library and shaders

**Operations:**

1. Detect platform: `linux`, `macos`, or `windows`
2. Set source paths (repo root)
3. Create target directory structure
4. **Copy for current platform:**
   - `lib/include/bg2e/` → `<target>/include/bg2e/` (all headers)
   - `bin/<platform>/libbg2e.so` (or `.dylib`) → `<target>/lib/<platform>/`
   - `bin/<platform>/shaders/*.spv` → `<target>/shaders/`
   - `assets/` → `<target>/assets/` (full directory)
   - `cmake/FindVulkan.cmake` → `<target>/cmake/`
   - `cmake/FindSDL2.cmake` → `<target>/cmake/`
   - `cmake/standalone_utils.cmake` → `<target>/cmake/`
   - On macOS: also copy Vulkan resources (MoltenVK, validation layers, icd.d, explicit_layer.d)
   - On Windows: copy both `.dll` and `.lib`

5. **Create placeholder directories for other platforms:**
   - For each platform NOT matching the current one, create `<target>/lib/<other_platform>/`
   - Write a `TODO.md` file in each explaining what files are needed

6. **Generate template files:**
   - `<target>/CMakeLists.txt`
   - `<target>/app/CMakeLists.txt`
   - `<target>/app/main.cpp`

### Step 6: Create batch script (`scripts/create_standalone_project.bat`)

Same logic as the bash script, adapted for Windows:
- Uses `%~dp0` to detect script location
- Uses `xcopy` / `robocopy` for directory copying
- Uses `copy` for single files
- Uses `if exist` for validation
- Generates template files using `echo` redirection
- Creates `lib/linux/TODO.md` and `lib/macos/TODO.md` with instructions

## Platform Placeholder: `TODO.md` Content

For each non-current platform, the script creates a `TODO.md` like:

```markdown
# Platform Libraries Required

This directory should contain the pre-compiled bg2e library for this platform.

## Required Files

### Linux (`lib/linux/`)
- `libbg2e.so` — the bg2e shared library

### macOS (`lib/macos/`)
- `libbg2e.dylib` — the bg2e shared library

### Windows (`lib/windows/`)
- `bg2e.dll` — the bg2e dynamic library
- `bg2e.lib` — the bg2e import library

## How to Obtain

Build bg2e-native on the target platform:
```
cmake -S . -B build -G <generator> -DVULKAN_SDK=/path/to/vulkan/sdk
cmake --build build
```

Then copy the library files from `bin/<platform>/` to this directory.
```

## Key Design Decisions

### 1. Pre-compiled library approach
- The generated project does NOT compile bg2e from source
- Only the user's app code is compiled at build time
- Shaders are pre-compiled `.spv` files (copied directly)
- App-specific shaders are compiled at build time using `glslang` from VulkanSDK

### 2. Cross-platform library handling
- **Current platform**: Binaries are copied directly into the generated project
- **Other platforms**: Empty directories with `TODO.md` are created
- This allows the user to generate on one platform and add other platform binaries later

### 3. RPATH / library discovery
- **Linux**: `bg2e.dll` is copied alongside the executable at build time (same dir), RPATH set to `$ORIGIN`
- **macOS**: dylibs bundled into `.app/Contents/lib/`, RPATH set to `@executable_path/../lib`
- **Windows**: `bg2e.dll` copied to output directory, `.lib` used at link time

### 4. Standalone `standalone_bundle_app()` vs original `bundle_app()`
The original `bundle_app()` depends on variables set by `lib/CMakeLists.txt`:
- `BG2E_INCLUDE_PATH`, `BG2E_LIB_TARGET`, `BG2E_SHADER_DIR`, `ASSETS_PATH`, `PRODUCT_DIR`

The standalone version uses:
- `${CMAKE_SOURCE_DIR}/include` for headers
- `${CMAKE_SOURCE_DIR}/shaders` for shaders
- `${CMAKE_SOURCE_DIR}/assets` for assets
- Pre-configured imported target `bg2e` for linking

### 5. Assets are fully copied
- The entire `assets/` directory is copied to the generated project
- The user can remove unnecessary assets after generation
- The user can add their own assets to the same directory

### 6. No modification of existing files
- `cmake/utils.cmake` is NOT modified
- `cmake/FindVulkan.cmake` and `cmake/FindSDL2.cmake` are copied as-is
- New `cmake/standalone_utils.cmake` contains standalone-specific functions

## Script Usage

### macOS/Linux:
```bash
cd /path/to/bg2e-native
./scripts/create_standalone_project.sh /path/to/my_project [project_name]
```

### Windows:
```batch
cd C:\path\to\bg2e-native
scripts\create_standalone_project.bat C:\path\to\my_project [project_name]
```

## Post-Generation Build Instructions

After generating the project:

```bash
cd /path/to/my_project
cmake -S . -B build -G Ninja -DVULKAN_SDK=/path/to/vulkan/sdk
cmake --build build
```

On Linux, the executable finds `libbg2e.so` via RPATH (`$ORIGIN`).
On macOS, the `.app` bundle contains all dylibs in `Contents/lib/`.
On Windows, `bg2e.dll` is copied to the output directory alongside the `.exe`.
