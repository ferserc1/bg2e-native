# Manual draw queue and binding probes

No target/CMake changes or execution by the agent. Include `probe.hpp` from a manually linked GPU/example runner.

- `runDrawQueueProbe(engine)` requires an initialized Engine, stopped producers and no active frame. It creates two submeshes and checks ancestor/drawable/local transforms, shared geometry with distinct object identities, disabled/hidden nodes, packed UV/channel/inversion/cutoff values, light placement, environment intent snapshots, transparent and solid-transparent sorting, visitor recovery after an invalid transform, and raster/query correspondence. Query extraction returns no instances on devices without acceleration support; opaque alpha-tested instances are retained on supported devices.
- `BindingProbe` compiles/loads the paired engine `draw/bindings/probe` stages through the existing shader integration. Initialize at a stopped boundary with the actual target format and acquired slot count. During an existing runner's frame, call record once using a loaded PNUUT scene and a validated environment snapshot created before acquisition. The probe prepares all four sets, draws all queue categories and restores color ShaderReadOnly. Its diagnostic pipeline deliberately has no depth/blending and is not the deferred renderer.

Lead checks:

1. Compile bg2e, existing production/draw examples and the manual fixture on available Vulkan/Metal. ResizeViewportVisitor must still accept VkExtent2D callers and generic width/height extents without importing render/native headers itself.
2. Render triangles inside clip coordinates using identity camera and distinct constant colors in all six linear texture slots. The diagnostic fragment value is `(six texture RGBs + sky(+X) + irradiance(+Y) + prefilter(+Z, maxLOD) + BRDF(0.5,0.5).rgb + material albedo RGB + first light RGB) / 12`; camera position is zero in this fixture. Compare float/byte readback within target tolerance. Vary frame camera and object transforms to verify both stage-specific UBO aliases.
3. Give UV0 and UV1 different gradients, independently vary all six scales/UV selections, scalar channels/inversions and alpha cutoff, and compare ShaderData packing/readback across native backends. Test manual sRGB decode on UNORM, automatic decode on native sRGB images, and rejection of native sRGB images marked as linear. Material alpha remains linear. AO texture presence is not a claim that an AO image contains a baked lightmap.
4. Alternate per-object attributes, lights, queue counts and environment snapshots while exercising all acquired frame slots. Retain the probe/slot records until completion, verify earlier submitted frames do not receive later values, and reject a second preparation for the same presentation number. Never bypass acquire/fence waiting or invent a frame number to update an in-flight slot.
5. Replace geometry/texture realizations at stopped boundaries, re-extract the queue and prepare/rebind the acquired slot. Direct in-place Texture reload/updateSampler invalidates an older queue and must require re-extraction. Frame records retain geometry, materials, textures and tracing owners; externally destroying resources with native cleanup is outside the contract.
6. Raster/query extraction must share the same stable nodeId/submesh and one-based frame object ID even after transparent sort. Default queries exclude both transparent classes; explicit opt-ins include each class. Opaque alpha-cutout metadata is retained for M01-11, which implements the actual alpha-aware hit table/shader. Test missing/unbuilt BLAS, wrong contexts and capacity overflow: these must fail, not silently drop geometry.
7. Production Drawable components, unresolved resources, unsupported UV/channel values, singular/nonfinite transforms and more than eight enabled lights must produce explicit errors. Reusing a visitor after failure must restore a complete new snapshot. No production visitor/binding behavior is migrated in this step.
