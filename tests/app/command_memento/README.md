# Generic command/memento contract sources

`main.cpp` is a standalone C++20 executable using public `bg2e::app` APIs, integer models and injected failures. It requires no testing framework or graphics/application initialization. It has not been compiled or run during step 2, and is intentionally not wired into CMake.

The assertions cover admission versus execution, FIFO scheduling, exactly-once completion/cancellation and stale callbacks, frozen preferences, nonrecordable origins, undo/redo branches and no-ops, recovered failures and fault blocking, composite compensation in both directions, preview adoption/cancellation, memory admission and shared-resource accounting, safe retirement, explicit eviction and saved document identity. Queue transaction checks cover absolute coalescing and boundaries that preserve ordinary update order.

## API contracts used by the sources

- Commands return allocation-free `CommandResult` values with static-lifetime diagnostics. `Failed`, `Rejected`, `Cancelled` and `NoOp` guarantee that the operation left the model unchanged. Implementations recover their own partial work; `Faulted` means recovery failed. Execute, undo, redo and interaction operations are `noexcept`.
- `CommandHistory::prepare` freezes metadata/context/preference policy, obtains memory estimates and allocates ownership/history storage. The move-only `CommandReservation` is consumed by `execute` or `beginTransaction`. Dropping it retires pending ownership. Core command state and pending reservations count against the same configured limits, including redo and active previews.
- Limits reject work before mutation. There is no implicit eviction on admission: use `discardOldest`, `discardRedo` or an explicit limit increase at a stable boundary. This deliberately prevents a failed/no-op action from deleting history. Shared resource/version tickets must use one stable identity and consistent byte estimate; duplicate tickets count once. Estimates must cover all retained data, including preparation and rollback. Native allocations are estimates, not measured driver usage.
- `CommandTransaction` supplies before-state capture, update estimates, preview updates and a final-change predicate. Commit adopts the active token without executing twice. Unchanged commit preserves redo. Cancel restores the captured baseline; recovered cancellation failure leaves the preview active for retry. `transactionId` identifies this specific preview for queued update/commit/cancel validation.
- `CommandQueue` schedules only one head, through an injected owner-thread executor. The application calls `pump` each tick. A delayed executor invokes one of its run/cancel callbacks at a safe boundary. Duplicate/late callbacks are ignored. Absolute coalescing only replaces an adjacent unscheduled update with matching interaction ID, document generation and exact target/property key; ordinary updates and commit/cancel break that adjacency. Superseded updates complete `NoOp`.
- Queue payloads are immutable CPU values with caller-supplied conservative size bounds. Property-key capacity is charged automatically. The queue defaults to a 1 MiB payload limit and 1024 pending jobs. Command reservations have a separate history budget; neither callbacks nor caller-supplied estimates allow precise accounting of allocator/driver overhead.
- Document IDs are unique even after branching or explicit eviction. Selection-only entries do not change the document token. A separate nonhistorical revision survives undo/redo. The application flushes preceding queue work and settles previews before save, then calls `markSaved` only after successful IO. `resetBaseline` requires a greater generation and invalidates pending old tokens. Fault recovery requires application repair/replacement before this reset.
- History/queue/destruction and all callbacks belong to their constructing thread. Calls from another thread are programming errors; producers must marshal. Commands and release sinks must not reenter mutation operations. Completion exceptions are isolated from history. The history must outlive its queue; call queue `shutdown` at a safe boundary to cancel pending work and restore its active preview. If cancellation fails, repair or retry before releasing application/device owners.
- `CommandReleaseSink` receives both the command and retained memory/resource tickets. An application that needs deferred GPU/module retirement retains both until safe. Without a sink, release is immediate on the owner thread. Deferred objects are no longer counted as history memory; their retirement service owns that separate in-flight budget. No core function waits on a GPU or cleans a scene object.
- Composite children have matching category/history policy and undo support. Document-impact children require a document-impact parent. No-op children are excluded from undo/redo. Recovery failure retains the whole composite and faults history.

Composer integration, widgets, scene adapters and application verification are outside this source harness and remain later plan steps.
